# Writing Notes

- **One note per system**, in `02-Systems`, made from the System template. It says how the system works now.
- **Properties first**: `type`, `status` (planned, live, retired) and `code:` (the files, with `#symbol` where a
  name matters). The vault check proves every `code:` path exists.
- **Plain and short.** A reader new to the system should follow it. Lead with what the system does for the game,
  then how, then its limits. Use a table or a Canvas where a picture says it faster.
- **Link, do not repeat.** Link other notes with `[[Note]]`; link the owner's decisions instead of quoting them.
- **No history.** No "used to", "was changed", dates or ticket names: that is git's job. A decision is the one
  dated record, and it lives in `05-Decisions` ([[Recording a Decision]]).
- **No game design the owner has not made** ([[The Owner Sets the Vision]]).
